¡Bienvenido al **Docs Site** oficial de **Cocktrail**! Aquí encontrarás toda la información técnica, arquitectónica y operativa sobre el ecosistema.

Cocktrail está construido bajo una filosofía ágil y segura, diseñada para funcionar a alta velocidad en entornos exigentes (como barras de discotecas y festivales).

---

## 🏗️ La Estructura del Monorrepo

El proyecto está organizado en un **monorrepo gestionado con pnpm workspaces**, lo que garantiza el acoplamiento óptimo de los tipos compartidos y la independencia en el despliegue de las aplicaciones.

El monorrepo se divide en:

*   **`packages/shared`** (`@cocktrail/shared`): Contiene los tipos de dominio, esquemas de validación y lógica compartida entre el cliente y el servidor.
*   **`apps/api`** (`cocktrail-api`): Servidor backend desarrollado en Express + TypeScript que maneja la persistencia, canjes, eventos en tiempo real (SSE) y la criptografía de tickets.
*   **`apps/web`** (`cocktrail-app`): Aplicación frontend web moderna desarrollada en Next.js 16 y Tailwind CSS v4, que aloja los flujos de clientes, administración y el panel KDS de barra.
*   **`apps/docs`** (`cocktrail-docs`): Este portal de documentación técnica, motorizado de forma dedicada por **Fumadocs**.

## 🧭 Los 4 Pilares de la Documentación

Nuestra documentación técnica se organiza en torno a cuatro ejes fundamentales para agilizar el onboarding de desarrolladores y operadores:

### 1. 🏁 Tutoriales
Guías de inicio rápido y paso a paso para configurar tu entorno local, levantar la base de datos in-memory o Supabase, y realizar tus primeros canjes de prueba.

### 2. 🧠 Conceptos
Exploración detallada de nuestro modelo de negocio, incluyendo el flujo criptográfico de los tickets QR (`READABLE-hmac`), el ciclo de vida de los pedidos, y la sincronización con Server-Sent Events (SSE).

### 3. 🛠️ Guías Técnicas
Manuales operativos específicos para el despliegue a producción, aseguramiento de la calidad (tests), y configuración de terminales de escaneo de barra.

### 4. 🔌 API Reference
Catálogo completo de los endpoints HTTP expuestos por `apps/api`, con ejemplos interactivos y definiciones de payloads utilizando esquemas Zod.
